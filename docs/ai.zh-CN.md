# AI 功能

SQL Notebook 可以让 DBX 中配置的模型协助写 SQL、解读结果、配置图表和生成大数字指标。所有 AI 调用都在插件界面中通过 `host.ai` 完成，后台进程不调用 AI。模型的输出只有在你点击「应用」「替换」「插入」等按钮后才会改动笔记本。

## 可用条件

- 需要 DBX 报告 AI 能力（`aiCompletion`）：文本生成需要 DBX 0.6.28 或更高版本；流式输出和取消需要 0.6.31 或更高版本（没有时使用一次性请求）。宿主没有 AI 能力时，AI 入口隐藏，开始页的 AI 设置处会说明原因。
- 插件需要 `host.ai` 权限。
- 同一时间只能有一个 AI 抽屉和一个 AI 请求。

## 功能

AI 入口打开右侧的抽屉（约占窗口宽度的 80%）：左侧是工作成果，右侧是多轮对话。对话输入框中 `Enter` 发送，`Shift+Enter` 换行。打开抽屉本身不发送任何内容；`Esc`、「放弃」或 ✕ 关闭抽屉，笔记本不变。

| 入口 | 作用 |
| --- | --- |
| SQL 区块的「✨ 问 AI」 | 与模型对话来生成或改写 SQL。左侧是可编辑的 SQL 草稿，可对照区块查看差异（默认折叠）。「试运行」在区块的连接上只读执行草稿，抽屉内最多显示 50 行，不写入笔记本。「确认写入」或「插入为新块」写入草稿 |
| SQL 区块的「📊 解读结果」 | 区块有结果时可用。打开即生成一次对结果的解读（Markdown 预览）。「插入为 Markdown 块」把它插入到打开抽屉的区块下方 |
| 图表区块的「问 AI」 | 生成最多 3 个图表方案，以摘要卡片和一个大预览显示；「应用」把选中方案的配置写入区块 |
| 大数字区块的「问 AI」 | 从笔记本中已有的本地结果表里生成候选指标卡片（每次回复最多 12 个）；可「更新当前块」（最多 8 个指标，需来自同一来源）或「插入为新块」（同一来源的指标合并为一个区块，每块最多 8 个） |

补充说明：

- SQL 写入后，只有在新 SQL 是单条只读的 `SELECT`/`WITH … SELECT`、没有未填的参数且上游结果是最新时，才会自动运行一次；否则显示原因，不运行。自动运行的判断是保守的文本分析：遇到 `$` 记号、反斜杠、`/*!`、`/*+` 注释或后面不是空白的 `--` 一律不自动运行。它只判断语句形态，不能识别 `SELECT` 中带副作用的函数。
- AI 生成的 SQL 在放入草稿前会格式化（按方言、保持 `{{ 参数 }}` 不变）；格式化结果只在版式和关键字大小写上与原文不同时才采用，否则使用原始 SQL。你自己输入的内容不会被格式化。
- 每次确认对应一步「已应用 · 撤销」（`Ctrl/⌘+Z`）；应用之后如果区块又被修改，撤销会被拒绝。
- 助手回复以 Markdown 渲染，原始 HTML、图片和非 http(s) 链接被丢弃。
- 关闭带有未应用改动的 SQL 抽屉时，会出现四个选项：更新 SQL 块、插入为新块、暂不处理（笔记本保持不变）、取消（抽屉保持打开）。

## 抽屉细节

- **解读抽屉**：打开即生成一次解读（已缓存的解读再次打开不发送；关闭「结果数据」时入口禁用）。抽屉里没有用于生成的按钮：在对话中输入就会生成，想重做时说「重新解读」。对话中模型的回复只有以 `UPDATE:` 开头时才会替换左侧预览；以 `ANSWER:` 开头或没有标记的回复只是回答，永远不改动预览。「插入为 Markdown 块」插入到打开抽屉的那个区块下方（即使之后区块被移动过）；该区块已被删除时按钮禁用并说明原因。
- **图表抽屉**：「生成方案」请求一组全新的方案，已有方案后同一按钮变为「重新生成」，替换整组方案。方案以摘要卡片显示，没有缩略图。对话中的修改只作用于**选中的**方案：模型返回一个配置时只替换该方案（延迟到达的回复不会移动选中项），返回一组配置时替换全部；重新打开抽屉会选中正在使用的方案。插件会把当前选中的方案编号随请求发送，在消息中写「方案 2」只是请求内容的一部分，由模型理解。「应用」使用预览的配置，区块或其列发生变化时禁用并说明原因。
- **SQL 抽屉**：「确认写入」在区块被修改（相对打开抽屉时）、草稿为空或草稿与区块相同时禁用并说明原因。「试运行」没有自己的取消和超时设置，并且一次只能进行一个。
- **大数字抽屉**：对话中的消息如「把指标 2 改成百分比」只改动那张卡片；返回整组候选时替换整组。「生成指标」（之后为「重新生成」）替换整组候选；「撤销」一步还原，包括移除所有插入的区块。来源结果变化后，抽屉会提示候选基于较旧的结构并重新检查，列已不存在时拒绝应用。
- 点击抽屉外的背景与点 ✕ 或按 `Esc` 等效（有未发送的草稿时会先询问是否放弃）；按下和松开都必须在背景上，所以在抽屉内拖选文字不会误关。
- 用输入法输入时，按 `Enter` 确认候选词不会发送对话消息，也不会提交导出文件名、开始页路径或路径输入框。
- SQL 语法高亮用于编辑器、差异视图和对话中的 `sql` 代码块，带有对宿主背景色的对比度保护（亮色、暗色和 DBX 预设）。超过 600 行的差异以纯文本显示，单个代码块的高亮上限为 512,000 个字符。

## 发送给模型的内容

每一轮对话都是**单个提示词**（`host.ai` 一次请求）：你的请求文字，加上作为不可信数据放在围栏中的当前 SQL、结果摘要或图表配置，以及此前的对话。你的请求文字最长 2000 个字符；整个请求最长 100,000 个字符，超出时先丢弃结果行，再丢弃表结构，对话则先丢最旧的轮次，请求中会说明被省略的内容。

设置在开始页的「AI 助手」中，三项默认都开启：

| 设置 | 开启时发送 |
| --- | --- |
| 表结构 | 表名、列名和类型；SQL 抽屉还会发送所在库/Schema 的表清单和相关表的结构 |
| 当前 SQL | 当前区块的 SQL 和早先回复中的 SQL |
| 结果数据 | 结果摘要和前几行（大数字最多 5 行样本和各列统计）、早先的解读和图表方案 |

- 每一轮都会重新检查这些开关，它们同样过滤对话历史：关闭「当前 SQL」后，早先回复中的 SQL 被替换为 `[earlier reply omitted]`；关闭「结果数据」后，数据部分和早先的解读/图表方案不再发送。你自己此前的消息按原文发送。
- 关闭「表结构」后不做任何目录查询，也不发送表清单和结构（大数字助手则不可用）。关闭「结果数据」后解读和图表助手不可用，大数字助手只根据名称生成候选。
- 数据库类型（如 `postgres`）会写入提示词，不受开关控制。
- 大数字候选卡片上的数值由本地用与区块相同的代码计算，不会发送给模型。
- 如果设置无法读取，插件按关闭处理，不发送任何可选内容。

## 同意确认

每次请求发出前，DBX 会弹出自己的确认框（显示插件、模型、提示词的首行和大小）。拒绝则请求取消，插件提示并且不做任何改动。插件自己不再提供预览；确认框是发送前唯一的关口。DBX 确认框中可以勾选「本工作区不再询问」（DBX 的会话内记忆，每个会话的第一次请求总会询问）。

## 表清单范围（SQL 抽屉）

「表结构」开启时，第一次提示词带有区块所在范围内的表清单：

- 区块设置了 Schema（Postgres 类）或数据库（MySQL 类）时，列出该范围的表；没有设置时，列出所有非系统 Schema 的用户表（`schema.table` 形式）。表清单最多 300 个名称。
- 模型需要更多信息时可以回复 `NEED_LIST: <schema>` 或 `NEED_TABLES: a, b`（最多 8 个名称），插件取回后自动再请求；每条消息最多自动追加 3 轮，第 4 次请求会给出提示并且不保存。每次读取显示一行提示。
- 目录查询是固定的语句，通过笔记本已有的 `host.data:read` 授权执行，不需要新权限。支持 Postgres、MySQL/MariaDB 和 SQLite；其他类型只使用笔记本中出现过的表并给出说明。
- 带引号或特殊字符的 Schema/数据库名不支持：名称只能由字母、数字和 `_ $ . -` 及空格组成（最长 64），否则提示并且不读取表清单。

## 不会写入文件的内容

AI 相关的请求、对话、备注、列信息和设置**从不**写入 `.sqlnb`、`.sqlnb.out` 或导出文件。

- 设置（发送开关、模型选择）保存在本机的 `host.storage`，不含 API 密钥。
- 对话按区块缓存在本机 `host.storage` 中（SQL、解读和图表的对话分别保存），重新打开同一路径的笔记本可恢复；抽屉中的「清空对话」会删除，删除区块也会删除其对话。上限：每块 40 条消息、60,000 个字符，单个存储值最多 200 KiB，最多 30 个区块、总计 400,000 个字符（先丢弃最旧的）。
- 重命名/移动文件或未保存的笔记本（没有路径）不会沿用对话；`host.storage` 失败时对话只保存在内存中。
- 缓存的消息可能含有来自数据的内容（AI 的 SQL、解读、图表方案）；它们只存在本机，并在发送时按开关过滤。

## 限制

- 一次只能生成一个结果；输出上限 2048 个 token，被截断或无法解析的输出会被拒绝（提示「输出过长」），不会部分应用。截断检测是启发式的：输出达到 8000 个字符才判定为截断，对中文输出 2048 个 token 可能先到上限，这时由解析和校验拒绝损坏的结构化输出，纯文本的解读只受长度上限约束。
- 宿主 `host.ai` 每次只接受单个提示词，所以对话历史是在提示词里拼接的，而不是多条消息。
- 关闭「表结构」后，你或模型早先的文字中仍可能出现表名或列名；自由文本无法可靠过滤，因此不保证。
- 「当前 SQL」关闭而「表结构」开启时，仍会从当前 SQL 中提取表名来取回结构（需要避免时关闭「表结构」）。
- 文本级的只读判断无法识别 `SELECT` 中带副作用的函数（如 `pg_sleep`、`nextval`、`load_extension`），宿主自身的只读约束是后盾。请在应用前检查 SQL。
- 数据库或宿主返回的错误文本会原样显示在界面中（插件不记录也不保存）。
- 判断解读是否仍与结果一致时，只比较列名、行数和前 20 行，之后的变化检测不到。
- 图表方案的预览在内存中聚合（日期粒度由 ISO 字符串推导，最多 2000 个分组），可能与实际图表略有差异。
- 大数字候选中引用了不存在的表/列、筛选条件无效、对比字段不是日期或聚合不兼容的会被标记，无法应用。
