# 已知限制

本页只列出当前仍然成立的限制。各功能的详细说明见 [区块能力](blocks.zh-CN.md) 和 [AI 功能](ai.zh-CN.md)。

## 验证范围

- 界面行为的自动检查在无头 Chrome 和 jsdom 中进行；在真实 DBX 宿主和用户自己的 Chrome 中的表现（真实主题颜色令牌、「高级设置」对话框、导出效果等）没有逐项验证。主题令牌缺失时使用浅色的备用色值，暗色主题下强调色可能偏弱。
- 候选包由 GitHub 工作流为五个平台构建，均为未签名；该工作流尚未在 GitHub 上实际运行过，首次发布时需要确认。
- 在没有 AI 能力的 DBX 0.6.48+ 宿主上，笔记本应不带 AI 入口正常工作，这一点尚未在真实宿主上验证。

## 运行与数据

- 每块最多取回和保存 1–5000 行（默认 5000），超出会被截断；依赖被截断结果的区块显示「基于部分数据」。
- 本地 SQL 引擎：查询超时 30 秒，整个会话最多注册 500,000 行，返回结果总体积上限 64 MiB，SQL 文本不超过 1,000,000 字节；只允许单条只读的 `SELECT`/`VALUES`。
- 本地 SQL 的单语句检查（Rust 的 `check_single_statement`）与 AI 自动运行使用的 TypeScript 判断（`analyzeSql`）是两套独立的实现，规则并不相同；前者基于文本，不识别 Postgres 的美元引号和反斜杠转义，也不单独处理 `/*!`、`/*+` 注释；本地引擎另有只读授权器作为后盾。
- 日期参数在本地 SQL 中按 ISO 文本比较，`<=`、`=` 和 `BETWEEN … AND {{d}}` 会漏掉当天；请用 `date(列) <= {{d}}` 或 `列 < 次日`。
- 本地 SQL 使用 SQLite 方言：`::` 转换、`ILIKE`、`DISTINCT ON`、`WITHIN GROUP`、`~` 正则运算符等不支持，`to_char` 只支持部分格式，详见 [spec/sqlnb-v1.md](../spec/sqlnb-v1.md) 4.3 节。
- 参数只能引用输入变量，不能引用其他区块的数据；MySQL 多字节客户端字符集（GBK、Big5、SJIS）的风险没有缓解，请使用 UTF-8 连接。
- 透视表最多显示 5000 行、500 列；图表分组点数过多时提示减少分组。界面最多添加 4 个行字段、3 个列字段、8 个值。

## 大数字

- 环比/同比按自然月比较，当前月份未结束时与上个月的完整数据比较，不按比例折算。
- 月份取日期文本的前 7 个字符，不做时区转换；数字、无法解析的文本和 NULL 视为没有日期。
- 文本筛选不能写成 `= ''`（空字符串不是有效值），匹配空单元格用「为空」；「包含」只对 ASCII 字母不区分大小写。

## 图表和标签

- 折线图/面积图的悬浮提示取舍：系列超过 10 个时只显示数值最大的 10 个并附「…另有 N 项」；X 轴稀疏（点很少或间距很大）时，鼠标会命中最近的 X，该 X 可能离鼠标较远；提示是纯文本。这些交互只在屏幕渲染中，导出的 HTML/PDF/SVG/PNG 是静态的，不含悬浮层，外观与之前一致，保存的 `.sqlnb` 和便携 `spec` 也不含这些内容。
- 便携的图表 `spec` 与插件的实际渲染有差异：`spec` 的周按周日起算而插件按周一，饼图/环形图只用第一个行字段和第一个值，直方图不做透视聚合。有透视配置时，保存会按配置重新生成 `spec`，覆盖手改的内容。
- 缩放、单位和分类值映射只影响显示，不进入排序、汇总、复制的数值和便携 `spec`。
- 标签输入框只在 change、失焦或 `Enter` 时提交。
- 行标题单元格不能用 `Tab` 到达（用「高级设置」对话框，或在表头上按 `F2`），汇总/总计表头也不可聚焦；列字段名在表上没有表头，只能在对话框中编辑。
- 「高级设置」对话框是 `position: fixed`，宽度跟随插件 iframe 而不是区块宽度；容器宽度约 640px 以下隐藏预览。预览的表头只是示意，不画提示框和导出效果；预览只取每个字段最多 3 个示例分类值，其余项没有徽标。

## Markdown 图片

- 只支持 PNG、JPEG、GIF、WebP；AVIF、JPEG XL、HEIC、SVG 不支持（显示替代文字或「不支持的图片」），没有以后支持的承诺。
- 远程 `http(s)` 图片不加载（插件不访问网络），只显示替代文字。
- 图片只能是笔记本所在文件夹及子文件夹里的文件，用相对路径引用；显示单张不超过 8 MiB、约 64 百万像素，粘贴单张不超过 10 MiB、一次最多 10 张，导出内嵌合计 50 MiB，超出的在导出中替换为替代文字。
- 图片首次加载时，后面的内容会移动一次。
- 磁盘上被修改的图片不会自动刷新：同一笔记本打开期间按路径缓存；重新打开笔记本（含同一路径）或另存为新路径后才重新读取。
- 撤销粘贴只移除链接，保存的图片文件留在磁盘上；插件从不自动删除图片，没有被引用的图片需要自己清理。
- 「另存为」只处理真正渲染成图片的链接（代码里的不处理）；跨行 alt 的图片链接不改写。参考式图片链接改写的是定义行：若同一个定义同时被普通链接使用，普通链接也会随之改变。
- 在插件之外移动或重命名 `.sqlnb` 文件而不带上图片，相对链接会失效（显示「找不到图片」）。
- 无法识别硬链接：指向文件夹之外内容的硬链接不会被发现。
- 粘贴只在剪贴板里有图片文件且没有文本时才生效。
- Windows 上的路径行为没有测试。
- 真实剪贴板和大笔记本的性能没有在真实 DBX 中验证。网页宿主里非图片文件拖入插件窗口会被忽略（插件会拦截默认的“打开文件”行为）。

## Markdown 工具栏与桌面拖放

- 桌面拖放通过宿主的 `fileTransfer.onDrop` 接收（运行时检测，不支持时降级为网页拖放）。DBX 桌面版此前按 Tauri 默认值启用原生拖放处理，文件拖放是否仍被拦截、是否确实触发 `onDrop`，**尚未在真实 DBX 中验证**；若仍被拦截，拖入无效，请改用粘贴或工具栏的「插入图片」。
- 系统拖放没有落点坐标：预览状态追加到末尾，编辑状态插到光标处；多个 Markdown 区块都没被点击过时只提示先点击区块。文件夹不保留结构。
- 同一次拖放可能同时触发网页事件和宿主事件：宿主给出 `dropId` 时按它判重；没有时按「文件名+大小」判重，1 秒内同名同大小的重复拖放可能被合并为一次。
- 宿主就绪（`ready`）后才订阅拖放，未出现时每 250 ms 重试，最多约 5 秒，之后放弃（桌面拖放不可用）。
- `Ctrl/⌘+B` 在真实 DBX 中可能与侧边栏快捷键冲突，待真机验证；冲突则需要去掉该快捷键。
- 工具栏「插入图片」使用宿主 `pick`：用户取消时宿主返回的形态未经真机确认（插件按空结果或带 cancel/abort 的错误视为取消）；`pick` 不可用时回退为浏览器文件选择框。
- 工具栏对粗体/斜体标记的识别是启发式，不是完整的 CommonMark 解析；`_` 形式的强调不处理；取消代码块会丢掉语言行。
- 编辑状态比预览状态多一行工具栏的高度（一行约 33 px，约 320 px 宽时折成两行约 63 px；工具栏与编辑框连成一体，无间距）。
- 工具栏、桌面拖放和图片粘贴的输入法（IME）行为以及 Windows/Linux 上的表现只在无头 Chrome 和 jsdom 中检查，**没有在真实 DBX 和真实输入法下验证**。

## 导出

- 导出中的语法高亮只覆盖 SQL，以及 Markdown 围栏的 sql、json、yaml、javascript/typescript、python、bash；html、xml、css、markdown 等其他语言按纯文本输出（为控制体积未打包对应解析器）。行内代码不着色。
- PDF 需要本机安装 Chrome、Edge 或 Chromium；没有时只能导出 HTML。自动找不到时，可在开始页「设置」中指定浏览器（输入路径，或用「选择文件…」「选择目录…」）。
- 导出完成提示框的「打开」交给系统打开器（macOS `open`、Windows `explorer`、Linux `xdg-open`）处理，插件无法得知是否真有程序打开了文件：没有关联程序或没有桌面环境时可能没有任何反应；只有启动打开器本身失败才显示错误。只能打开本次运行中刚导出的文件，重启插件后需在文件管理器中手动打开。
- 导出文件位于网络位置（Windows 的 UNC 路径，如 `\\server\share\…`）时，「打开」不会执行，只提示在文件管理器中打开，以免触发对网络共享的自动访问；导出本身不受影响。Windows 上文件名含逗号时，「打开」使用 `explorer` 的行为没有实测。
- 结果表列宽按字符数估算：宽字形（大写 W、emoji）和很宽的数值列可能比估算更宽而溢出，序号列不计入估算。
- 样式使用 `color-mix()`：不支持它的旧 webview 或 PDF 引擎会丢失引用、代码、表头的淡色背景。

## AI

- 数据库/宿主返回的错误文本按原样显示。
- 文本级的只读判断无法识别 `SELECT` 中带副作用的函数（如 `pg_sleep`、`nextval`、`load_extension`）；自动运行只在语句形态为单条只读 `SELECT`/`WITH … SELECT` 时进行，请在应用前检查 SQL。
- 输出上限 2048 个 token；截断检测是启发式的（8000 个字符），对中文输出可能不触发，此时由解析和校验拒绝损坏的结构化输出。
- 关闭「表结构」后，自由文本中的表名和列名无法可靠过滤；「当前 SQL」关闭而「表结构」开启时仍会从 SQL 中提取表名。
- 表清单最多 300 个名称；非公开 Schema/数据库的清单依赖宿主 `queryData` 的 `schema`/`database` 字段和 `getTableMetadata` 的 schema 参数，宿主是否遵守尚未验证；MySQL 的 Schema 建议来自 `SHOW DATABASES`，包含系统库；带引号或特殊字符的 Schema 名不支持；找不到和无权读取的表无法区分。
- 重命名或移动文件、未保存的笔记本不会沿用对话缓存；对话不在多台机器之间同步，且受 `host.storage` 配额限制。
- 解读是否过期只比较列名、行数和前 20 行。
- 图表方案的预览在内存中聚合（最多 2000 个分组），可能与实际图表略有不同。
- DBX 的确认框是发送前唯一的关口，插件自己不提供预览。

## 历史记录

撤销/重做覆盖文档内容的所有修改（见 [区块能力](blocks.zh-CN.md)），只用键盘，上限 200 步或约 16 MB，历史只在内存中。已知限制：

- 不还原运行结果和运行状态：撤销删除会还原区块，但需要重新运行；撤销不会取消正在运行的查询。
- 不覆盖选中等界面状态和 AI 对话。
- 普通输入框、文本框和下拉框内使用浏览器自己的撤销，与笔记本历史分开。
- 数字和日期输入框没有输入法组合处理。
- 屏幕阅读器的实际朗读效果尚未在真实读屏软件中验证。

### 扩展点：笔记本历史

`plugin/ui-src/src/state/history.ts` 提供通用的撤销/重做栈（`store.history`、`store.undo()`、`store.redo()`，上限 200 步或约 16 MB）。栈里的文档条目是基于差异的 `DocEntry`（`docHistory.ts`）：只保存受影响区块（以及可选的顺序、`settings`、`connections`、`metadata`）修改前后的快照，不是整份文档。其他修改要接入时：

1. 不要自己往栈里推条目，而是用 `recordEdit(label, source, touched, mutate)` 包住修改：`touched` 声明受影响的区块 id（`ids`）、是否改变顺序（`order`）和文档级字段（`doc`）；`recordEdit` 在 `mutate()` 前后调用 `cloneTouched` 取得 `before`/`after`，两者相同则不记录，否则生成 `DocEntry`（由 `applyDelta` 执行撤销/重做）。
2. 冲突检查由 `checkDelta` 完成：撤销时受影响的区块和文档级字段必须仍等于 `after`，重做时必须等于 `before`（图表的派生字段 `metadata.spec` 不参与比较），否则返回 `'conflict'`：栈不会执行该条目，丢弃它，界面显示「该块已被修改，无法撤销」。
3. 文档修改通过 `recordEdit` 记录，连续输入在 800 ms 内合并；输入法组合期间不记录，组合结束时记录一步。SQL 编辑器已去掉自己的历史，其快捷键直接调用笔记本历史；全局快捷键 `useHistoryShortcuts` 忽略普通输入框、文本框、下拉框和可编辑内容。
4. 上限、清空（加载、另存为、关闭时清空，普通保存不清空）和撤销/重做成功后的状态标记由栈和 store 处理。
